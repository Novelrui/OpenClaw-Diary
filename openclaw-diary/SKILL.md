# 🦞 OpenClaw-Diary Setup Guide

Help users set up OpenClaw auto learning diary with this complete workflow.

## Architecture Overview

The diary uses a **JSON data-driven architecture**:

```
diary-data.json     → Config only (title, subtitle, footer)
diary/
  index.json        → List of all dates
  2026-05-03.json   → Single day's entries
  2026-05-04.json   → Another day's entries
  ...
scripts/
  build.js          → Merges all data into dist/ for deployment
index.html          → Source HTML (fetches diary/ files at runtime)
dist/               → Built output for GitHub Pages (auto-generated)
```

**To add a new diary entry**: Create `diary/YYYY-MM-DD.json`, update `diary/index.json`, then run `node scripts/build.js`.

**NEVER manually edit `dist/` files** — they are generated by the build script.

## Complete Workflow

### Step 1: Guide User to Fork the Repo

Tell user to fork on GitHub:

```
Please fork the repo:
1. Visit https://github.com/YAI-Lab/OpenClaw-Diary
2. Click "Fork" button
3. Select your account, complete fork
```

### Step 2: Get User's Fork URL

Ask for the forked repo URL, format:
```
https://github.com/your-username/OpenClaw-Diary
```

### Step 3: Personalize Configuration (IMPORTANT!)

**After cloning the repo, modify `diary-data.json` config section:**

```json
{
  "config": {
    "title": "YourRobotName 的学习日记",
    "subtitle": "每天学习 · 每天成长",
    "filename": "ai-learning-diary.json",
    "footerText": "🦞 由 YourRobotName 自动生成",
    "footerLink": {
      "text": "YourRobotName",
      "url": "https://github.com/your-username"
    }
  }
}
```

Also update the `<title>` tag in `index.html` if desired.

### Step 4: Get GitHub Token

If GitHub token not configured, user needs to create:

1. Visit https://github.com/settings/tokens
2. Click "Generate new token (classic)"
3. Check `repo` permission
4. Generate and save token

**Important**: Must tell user the purpose when getting token, and how to revoke.

### Step 5: Configure Daily Cron Task

Use cron or heartbeat to configure daily task:

**Method A: Cron Task**
```bash
# Run daily at UTC 1:00 (9:00 Beijing time)
openclaw cron add "0 1 * * *" "Daily Learning Diary" "Read latest AI news, track GitHub stars, generate report and push to OpenClaw-Diary repo"
```

**Method B: Heartbeat Task**
Add to HEARTBEAT.md:
```markdown
## Daily Learning Report
- Research latest AI/tech/politics news
- Track GitHub repo stars growth (if user has repos)
- Generate report in user's language
- Push to OpenClaw-Diary
```

### Track GitHub Stars Growth

As part of the daily report, optionally track GitHub stars:

```bash
# Get current stars
curl -s https://api.github.com/repos/owner/repo | jq '.stargazers_count'

# Track daily growth
# Store in a simple JSON file or append to diary
```

### Step 6: Push Daily Diary Entry

**This is the daily workflow for adding new diary content:**

1. Create a new date file: `diary/YYYY-MM-DD.json`
2. Add the date to `diary/index.json` (at the beginning of the `dates` array)
3. Run the build script: `node scripts/build.js`
4. Commit and push

```bash
# Example: Add today's diary
# 1. Create diary/2026-05-04.json with content (see template below)

# 2. Update diary/index.json - prepend the new date
# "dates": ["2026-05-04", "2026-05-03", "2026-03-03", ...]

# 3. Build dist/
node scripts/build.js

# 4. Commit and push
git add diary/ dist/ diary-data.json
git commit -m "📝 $(date '+%Y-%m-%d') diary entry"
git push origin main
```

### Step 7: Enable GitHub Pages

1. Go to user's forked repo
2. Settings → Pages
3. Source: Deploy from a branch
4. Branch: main, folder: `/ (root)` — **or** configure to serve from `dist/` if preferred
5. Save, wait for deployment

**Note**: The `dist/` directory contains the built version with inline data (works with `file://` protocol). If serving from root, ensure `dist/index.html` is served as the main page, OR configure GitHub Pages to serve from `dist/`.

## Daily Diary Content Template

**Each day's diary is a JSON file at `diary/YYYY-MM-DD.json`:**

```json
{
  "date": "2026-05-04",
  "entries": [
    {
      "filename": "~/2026-05-04/learning.md",
      "status": "modified",
      "sections": [
        {
          "type": "quote",
          "title": "💡 Today's Learning",
          "content": "<p>What I learned today...</p><ul><li>Item 1</li><li>Item 2</li></ul>"
        },
        {
          "type": "key-value",
          "items": [
            {
              "key": "\"papers_read\"",
              "value": "3",
              "comment": ", // arXiv papers",
              "valueType": "number"
            },
            {
              "key": "\"repos_starred\"",
              "value": "5",
              "comment": " // GitHub repos",
              "valueType": "number"
            }
          ]
        },
        {
          "type": "terminal",
          "command": "git log --oneline -3"
        }
      ]
    },
    {
      "filename": "~/2026-05-04/thinking.md",
      "status": "modified",
      "sections": [
        {
          "type": "quote",
          "title": "🤔 Some Thoughts",
          "content": "<p>Reflections on today's learning...</p>"
        }
      ]
    }
  ]
}
```

### Available Section Types

| Type | Fields | Description |
|------|--------|-------------|
| `quote` | `title`, `content` (HTML) | Blue-bordered content box with title |
| `long-text` | `content` (HTML) | Plain text content without border |
| `terminal` | `command`, `output` (optional, HTML) | Terminal command with optional output |
| `key-value` | `items[]` with `key`, `value`, `comment`, `valueType` | Key-value pairs with syntax highlighting |

### Entry Status Values

| Status | Meaning |
|--------|---------|
| `modified` | Entry has been updated |
| `ready` | Entry is prepared |
| `sent` | Entry has been delivered |
| `✓` | Entry is complete |

### Entry Filename Patterns

The `filename` field follows these patterns (used for type filtering):

| Pattern | Filter Category |
|---------|----------------|
| `*learn*` or `*learned*` | 💡 Learning |
| `*think*` | 🤔 Thinking |
| `*tomorrow*` or `*plan*` or `*todo*` | 📋 Plans |
| `*message*` or `*msg*` or `*letter*` | ✉️ Messages |
